## 一、核心设计理念

### 1.1 要解决的问题

当前成长几乎全靠「刷怪 → 随机品阶饰品 → 随机词条」。玩家无法：

- 稳住一件喜欢的饰品主题，只改善数值
- 消化多余低品阶饰品
- 把战斗收益转化为可控强化

锻造台补上 **可控成长**，但不替代野外掉落与 Boss 高品阶池。

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **强化 ≠ 换品阶物品** | 默认强化不产出「下一品阶同品种饰品」；物品 ID / 品阶前缀保持不变 |
| **强化叠层** | 强化在原物品上叠加独立强化层（DataComponent），可粉碎回收 |
| **重锻分三档** | 普通只滚基础词条；高级滚基础+强化且数值偏高；锁定石搭配前两者锁定指定词条 |
| **特例升阶可插拔** | 少数指定物品（套装件、专武等）可走「升阶配方」旁路，不污染通用强化 |
| **材料分类型** | 1～3 种主材料对应装备大类；品阶碎片决定强化成功率（与物品掉落品阶对比） |
| **材料掉率独立体系** | 类型精华 : 品阶碎片 : 属性精华 = 6:2:1，独立判定，**不挂靠饰品掉率**（V1.16，见 §8.2） |
| **JSON 管数值** | 区间、消耗、成功率进 JSON；Java 只写逻辑与回退 |

### 1.3 与现有系统的边界

```
掉落（已有）          锻造台（本策划）
─────────────         ─────────────────
GLM → 饰品成品        强化：叠强化层
词条滚动 → 基础词条    重锻：重滚基础词条
品阶 = 物品 ID 前缀    特例升阶：换物品 ID（白名单）
entity loot 空池 ──►  材料掉落落点
```

**禁止：** 用通用强化把 Broken 饰品「炼成」Legendary 同款物品，从而绕过 Boss / 高难宝箱品阶池。

## 二、锻造台玩法线

锻造台 UI 建议 4 个模式页签（V1 可先做前 3 个）：

| 模式 | 输入 | 输出 | V1 |
|------|------|------|----|
| **强化** | 装备 + 1×类型精华 + 1～10×同种品阶碎片 | 同物品强化 +1（上限 +10）；成功率见 §4.4 | ✅ |
| **强化（属性精华）** | 装备 + 1×属性精华 | 为物品添加该属性基础词条，次数 +1（§4.5，并入强化页签） | ✅ |
| **重锻** | 装备 + 普通/高级重锻石 +（可选）锁定重锻石 | 按石种重滚词条；可锁定部分词条 | ✅ |
| **粉碎** | 已强化装备 | 品阶碎片约 50% 回流；类型精华约 25% 概率回流 | ✅ |
| **升阶** | 白名单装备 + 升阶材料 | 下一品阶同主题物品（或指定产物） | ⏳ 预留 |

### 2.1 槽位示意（强化）

```
┌──────────────────────────────────────────┐
│  [装备槽]  [类型精华×1]  [品阶碎片×1～10] │
│  ※ 单次只能放同一种品阶碎片              │
│           ↓  预览成功率与强化结果         │
│              [输出预览]                   │
│         [确认强化]                        │
└──────────────────────────────────────────┘
```

### 2.2 槽位示意（重锻）

```
┌──────────────────────────────────────────────────┐
│  [装备槽]  [普通或高级重锻石]  [锁定重锻石 可选]   │
│                                                  │
│  锁定栏：勾选要保留的词条（消耗锁定石，见 §5.3）  │
│           ↓  预览重锻结果                         │
│              [输出预览]                           │
│         [确认重锻]                                │
└──────────────────────────────────────────────────┘
```

## 三、材料体系

### 3.1 三类主材料（推荐定稿）

| ID（建议） | 名称 | 作用对象 | 强化方向池（在区间内随机挑 1～2 条） |
|------------|------|----------|--------------------------------------|
| `accessory_essence` | 饰品精华 | 饰品 | 生命 / 攻击 / 护甲 / 暴击 / 减伤 / 移速 等（与饰品词条轴对齐） |
| `weapon_essence` | 武器精华 | 武器（后期） | 攻击 / 穿透 / 暴击率 / 暴击伤害 |
| `armor_essence` | 护甲精华 | 护甲（后期） | 护甲 / 减伤 / 生命 / 抗性类 |

V1 可只实装 **饰品精华**；武器/护甲精华先注册物品与掉落，强化逻辑挂「未开放」提示，避免以后改 ID。

### 3.2 品阶强化材料（与饰品品阶一一对应）

材料档与 `AccessoryDropRarity` / 饰品命名前缀 **完全一致**（共 6 种）：

| 品阶枚举 | 饰品前缀 / 展示名 | 材料 ID（建议） | 材料中文名 |
|----------|-------------------|-----------------|------------|
| BROKEN | `broken_` / 残破 | `rank_shard_broken` | **残破品阶碎片** |
| NORMAL | （无前缀）/ 普通 | `rank_shard_normal` | **普通品阶碎片** |
| EXCELLENT | `excellent_` / 优秀 | `rank_shard_excellent` | **优秀品阶碎片** |
| EPIC | `epic_` / 史诗 | `rank_shard_epic` | **史诗品阶碎片** |
| LEGENDARY | `legendary_` / 传说 | `rank_shard_legendary` | **传说品阶碎片** |
| MYTHIC | `mythic_` / 至臻 | `rank_shard_mythic` | **至臻品阶碎片** |

说明：

- 中文品阶名与饰品一致：残破、普通、优秀、史诗、传说、至臻（物品展示为「残破·xxx」；引导书若写「破损」应统一为「残破」）。  
- 品阶材料 **不改变** 物品掉落品阶，**不**用于解锁更高强化阶（上限仍为 +10）。  
- 职责：按「物品品阶 vs 材料品阶」决定强化成功率（见 §4.4）。  
- 旧名「凡铁 / 精金 / 星辉」作废。

### 3.3 重锻材料（三种）

| ID（建议） | 名称 | 单独使用？ | 作用 |
|------------|------|------------|------|
| `reroll_stone` | 普通重锻石 | ✅ 可单独 | 仅重滚 **基础词条**（`ACCESSORY_ATTRIBUTES`）；**保留**强化层 |
| `reroll_stone_advanced` | 高级重锻石 | ✅ 可单独 | 重滚 **基础词条 + 强化词条**；数值分布偏高（见 §5.2） |
| `reroll_stone_lock` | 锁定重锻石 | ❌ 须搭配 | 锁定指定词条后再重锻；**必须**与普通或高级重锻石同次使用 |

说明：

- 锁定石 **不能单独重锻**；放入锻造台时须同时有普通石或高级石。  
- 一次重锻最多消耗：**1×（普通或高级）+ 至多 2×锁定石**（每锁 1 条耗 1 个）。  
- 旧文档中的「单一重锻石 / V1.1 才做锁定」作废，以本表为准。

### 3.4 材料数量原则

- 材料共 22 种 = 3 种类型精华（§3.1）+ 6 种品阶碎片（§3.2）+ 3 种重锻石（§3.3）+ **10 种属性精华（§3.5）**，详见对应小节。
- 不建议再拆「火/冰/雷」主题材料到 V1（主题绑定留给特例升阶或精英专属掉落彩蛋）

### 3.5 属性精华（V1.14 新增，10 种）

为「没有该属性的物品」添加该属性的**基础词条**，实现跨属性成长。属性精华添加的属性与掉落词条同属基础词条（`ACCESSORY_ATTRIBUTES`），不占强化层。

| ID | 名称 | 对应属性 |
|----|------|----------|
| `attribute_essence_life` | 生命精华 | `max_health` |
| `attribute_essence_attack` | 攻击精华 | `attack_damage` |
| `attribute_essence_armor` | 护甲精华 | `armor` |
| `attribute_essence_speed` | 移速精华 | `movement_speed` |
| `attribute_essence_luck` | 幸运精华 | `luck` |
| `attribute_essence_regen` | 生命恢复精华 | `health_regen` |
| `attribute_essence_penetration` | 护甲穿透精华 | `armor_penetration` |
| `attribute_essence_crit_chance` | 暴击精华 | `crit_chance` |
| `attribute_essence_crit_damage` | 暴击伤害精华 | `crit_damage` |
| `attribute_essence_reduction` | 减伤精华 | `damage_reduction` |

说明：

- **用途**：给没有该属性的物品添加该属性基础词条（如生命戒指加攻击力、幸运值）。
- **使用条件**：物品基础词条中该字段为 0（已有该属性则无法再使用，拒绝）；同一属性只能添加一次。
- **消耗**：1× 对应属性精华；**必成功**（V1.14 定稿）。
- **占用强化次数**：每次属性精华添加使物品强化次数 +1（计入 +10 上限，见 §4.5）。
- **掉落来源**：**V1.16 定稿**——属性精华掉率 = 品阶碎片的一半（独立判定，见 §8.2 材料掉率表），按 §4.3 方向权重细分。

## 四、强化规则

### 4.1 强化是什么

对目标装备写入独立组件（建议名 `FORGE_ENHANCEMENT`），例如：

```text
enhance_level: 0~N
spent_materials: { accessory_essence: k, ... }   // 供粉碎结算
bonus: { attackDamage: x, critChance: y, ... }  // 本次累计强化加成
history: 可选，用于 UI 展示最近几次方向
```

- **物品注册名不变**（`excellent_life_essence_ring` 仍是 Excellent）  
- **基础词条**仅在使用普通/高级重锻时重滚；**强化加成**仅在使用高级重锻时重滚（普通重锻保留）  
- 最终属性 = 基础词条 + 套装/效果 + **强化加成**

#### 4.1.1 强化次数显示（V1.9 定稿）

强化后，物品名称末尾附加 `+N`（N = 当前 `enhance_level`）：

| 情况 | 显示示例 |
|------|----------|
| 未强化（N=0） | `生命精华之戒`（无后缀） |
| N=1 | `生命精华之戒 +1` |
| N=10 | `生命精华之戒 +10` |

规则：

1. **格式**：`物品名 +N`，`+N` 与名称间一个空格，`N` 使用半角数字；品阶前缀（如「史诗·」）不受影响，示例 `史诗·生命精华之戒 +3`。
2. **来源**：从 `FORGE_ENHANCEMENT` 组件的 `enhance_level` 读取，不额外存储；N=0 时不显示后缀。
3. **同步时机**：强化成功 +1、普通/高级重锻（强化阶保留，显示不变）、粉碎（装备销毁，无显示问题）、特例升阶（换新物品，后缀清空）。
4. **实现提示**：展示名建议运行时拼接（不写死物品名），避免 lang 冗余；高级重锻时 `enhance_level` 不变故 `+N` 不跳变，仅强化加成数值变化。
5. **与 Patchouli 引导书的关系**：引导书示例物品用文字描述展示名，不引用动态 `+N`。

#### 4.1.2 属性 Tooltip 明细显示（V1.10 定稿）

悬停物品默认显示**最终属性**（基础 + 强化总和）；按住 Shift 显示**基础 / 强化明细**。

| 显示模式 | 示例（最大生命值：基础 10 + 强化 10） |
|----------|--------------------------------------|
| 默认（未按 Shift） | `最大生命值: +20` |
| 按住 Shift | `最大生命值: +20（基础 +10 / 强化 +10）` |

规则：

1. **最终属性** = 基础词条（`ACCESSORY_ATTRIBUTES`）+ 强化加成（`FORGE_ENHANCEMENT.bonus`），同键相加后显示。
2. **Shift 明细**：每属性显示「基础 +N / 强化 +N」两段；强化为 0 可省略强化段，基础为 0 仅显示强化段。
3. **Shift 检测**：`Screen.hasShiftDown()`（客户端渲染 tooltip 时判断），与原版高级提示（F3+H）互不影响。
4. **键名对齐**：基础词条为 camelCase（如 `maxHealth`），强化方向键为 snake_case（如 `max_health`，见 §4.3），实现时提供「显示键 ↔ 基础字段 ↔ 强化键」映射表。
5. **生效口径一致**：玩家实际生效属性 = 基础 + 强化（§4.1），显示必须与真实数值一致；后续若套装等加成并入最终属性，需同步本表。
6. **不参与拆分的项**：套装效果、静态特殊效果（守护手镯抗性等）保持原样，不进明细。
7. **实现位置**：`AccessoryTooltipHelper.addAccessoryTooltips`，将 `addStatLine` 重构为「合并 / 明细」两种模式；无 `FORGE_ENHANCEMENT` 时两种模式输出相同。
8. **注意**：强化方向池共 10 个方向（§4.3，V1.11 起），与基础词条 10 个字段**一一对应**，合并显示可全覆盖。

### 4.2 单次强化流程

1. 校验：物品类型匹配精华大类；`enhance_level < 10`；放入 **1×** 类型精华 + **1～10×** 同种品阶碎片  
2. 按 §4.4 计算成功率并掷骰  
3. 无论成败：消耗本次放入的精华与全部品阶碎片，并记入 `spent_materials`  
4. 失败：**强化阶不掉**（V1）  
5. 成功：`enhance_level += 1`；从精华对应方向池抽强化加成——**75% 概率抽 1 条，25% 概率抽 2 条**（V1.8 定稿）；数值在 JSON 区间内随机  

### 4.3 强化方向随机（饰品精华示例）

每次成功强化：**75% 概率抽 1 条、25% 概率抽 2 条**强化方向（V1.8 定稿）；方向按权重随机，数值在**按品阶分档的增量区间**内随机（V1.12 定稿，见 §4.3.1）。

| 方向键 | 权重 | 说明 |
|--------|:---:|------|
| `max_health` | 20 | |
| `attack_damage` | 18 | |
| `armor` | 15 | |
| `crit_chance` | 12 | 小数 |
| `crit_damage` | 10 | |
| `damage_reduction` | 10 | |
| `armor_penetration` | 9 | V1.11 新增 |
| `movement_speed` | 8 | |
| `health_regen` | 7 | |
| `luck` | 6 | V1.11 新增；影响掉落，权重偏低 |

> V1.11 扩充：强化方向池补齐为 **10 个方向**，与基础词条 10 个字段一一对应。

> **强化范围（V1.14 定稿，推翻 V1.13 决策 A）**：强化方向池 **= 物品当前已有属性的集合**——即基础词条中非 0 的字段（含属性精华添加的），在集合内按权重归一化；物品只有 1 个属性则 100% 强化该属性。**不允许强化出物品没有的属性**。跨属性成长统一由**属性精华**（§3.5）实现：先用精华添加属性（占强化次数），再对该属性进行强化。若物品没有基础词条（从未掉落滚动），强化不可用（需先重锻出基础词条或使用属性精华）。

#### 4.3.1 增量区间按品阶分档（V1.12 定稿）

**机制**：每级强化增量区间 = 该物品该属性在 `attributes/ranges.json` 的**基础区间** × **品阶每级系数**。采用**区间挂钩**（非 roll 值挂钩）：同一品阶同属性共享同一增量区间，不随单件 roll 出的具体值波动，保证同品阶强化收益可预期、不滚雪球。

**品阶每级系数：**

| 品阶 | 每级系数 | 满强化 +10 约为基础值 | 理由 |
|------|:---:|:---:|------|
| BROKEN | 7% | +70% | 前期装备弱，强化占比高、有手感 |
| NORMAL | 6% | +60% | |
| EXCELLENT | 5.5% | +55% | |
| EPIC | 5% | +50% | |
| LEGENDARY | 4.5% | +45% | |
| MYTHIC | 4% | +40% | 基础绝对值已大，40% 同样明显 |

**示例验证（每级增量 = 基础区间 × 系数）：**

| 方向 | BROKEN | NORMAL | EXCELLENT | EPIC | LEGENDARY | MYTHIC |
|------|--------|--------|-----------|------|-----------|--------|
| `max_health` | 0.07～0.21 | 0.24～0.36 | 0.33～0.55 | 0.50～0.70 | 0.68～0.90 | 0.80～1.20 |
| `attack_damage` | 0.007～0.035 | 0.03～0.09 | 0.083～0.165 | 0.125～0.20 | 0.18～0.27 | 0.24～0.36 |

其余 8 个方向按同一公式由 `ranges.json` 推导（不手配 60 个硬编码区间）；完整数值以 `enhance_rolls.json` 为准。

**显示精度（V1.12 定稿）**：强化属性 Tooltip 统一**保留 3 位小数**，覆盖 movement_speed / crit_chance / damage_reduction / luck / health_regen 等低品阶增量仅 0.001 量级的属性，避免显示为 +0.0。

### 4.4 强化上限与成功率（V1.3 定稿）

#### 4.4.1 强化上限

| 项 | 规则 |
|----|------|
| 全局上限 | **所有装备强化阶最多 +10**（与掉落品阶无关） |
| 品阶碎片 | **不**再用于解锁更高上限 |

#### 4.4.2 品阶索引（六阶对齐）

物品档 `I` 与材料档 `M` 使用同一套枚举序（0～5）：

| 档位 | 品阶 | 物品示例 | 材料 |
|------|------|----------|------|
| 0 | 残破 BROKEN | `broken_*` | 残破品阶碎片 |
| 1 | 普通 NORMAL | 无前缀饰品 | 普通品阶碎片 |
| 2 | 优秀 EXCELLENT | `excellent_*` | 优秀品阶碎片 |
| 3 | 史诗 EPIC | `epic_*` | 史诗品阶碎片 |
| 4 | 传说 LEGENDARY | `legendary_*` | 传说品阶碎片 |
| 5 | 至臻 MYTHIC | `mythic_*` | 至臻品阶碎片 |

```
delta = I - M
```

- `delta < 0`：低阶物品用高阶材料 → 差距越大，每份加成越高  
- `delta = 0`：同品阶 → 每份 **+25%**  
- `delta > 0`：高阶物品用低阶材料 → 差距越大，每份加成越低；**凡跨两阶及以上（delta≥+2），满 10 份总成功率必须 &lt; 50%**

#### 4.4.3 成功率公式

```
count ∈ [1, 10]          // 单次放入的同种品阶碎片数量；超过 10 UI 禁止
bonus = BonusTable(delta) // 见下表（每个碎片）
success = min(1.0, count × bonus)
```

### 4.5 属性精华操作（V1.14 定稿，并入强化页）

属性精华为物品添加「它没有的」属性基础词条，实现跨属性成长。

| 项 | 规则 |
|----|------|
| 入口 | 锻造台**强化页签**内，与强化并列的操作 |
| 放入 | 装备 + 1× 对应属性精华（§3.5 表） |
| 条件 | 物品基础词条中该属性为 0；已有该属性则拒绝（同一属性只能加一次） |
| 消耗 | 仅 1× 属性精华（不消耗类型精华/品阶碎片） |
| 成功率 | **必成功**（V1.14 定稿） |
| 效果 | 为该物品添加该属性基础词条；数值按「品阶标准区间」抽取（见 §5.2.1） |
| 强化次数 | 每次添加 **+1**，计入 +10 上限；物品名 `+N` 随之累加（§4.1.1） |
| 失败/次数不足 | 若已达 +10，无法再添加（与强化共用上限） |
| 掉落 | **V1.16 定稿**——属性精华掉率 = 品阶碎片的一半（§8.2），按 §4.3 方向权重细分 |

**与强化/重锻的协作流程示例：**

```text
1. 生命戒（仅 max_health）→ 用 攻击精华 → 获得攻击力基础词条，次数 +1（0/10 → 1/10）
2. 对「攻击力」进行强化 → 从 {生命, 攻击} 池中抽取方向，次数 +1
3. 普通重锻 → 保留 {生命, 攻击} 两个维度，但数值全部随机重置
```

## 五、重锻规则

重锻 **100% 成功**（无失败惩罚）；成本完全由石种稀缺度体现。

### 5.1 普通重锻石（`reroll_stone`）

| 项 | 规则 |
|----|------|
| 消耗 | 1× 普通重锻石；**EPIC 及以上品阶（史诗/传说/至臻）一次重锻消耗 2×**（V1.8 定稿） |
| 重滚范围 | **仅基础词条**（`ACCESSORY_ATTRIBUTES`） |
| 属性维度 | **保留全部属性维度**（掉落词条 + 属性精华添加的），**但数值全部随机重置**（V1.14 定稿）——用属性精华添加的属性不会被洗掉，只是数值重抽 |
| 强化层 | **完整保留**（等级、方向加成、`spent_materials` 均不变） |
| 数值分布 | 与掉落滚动相同（`AttributeRollerEvents` / `ranges.json` 标准区间）；属性精华添加的属性若物品自身 `ranges.json` 无该属性，按**品阶标准区间**取值（§5.2.1） |
| 可搭配锁定 | ✅ 可与锁定重锻石同用 |

### 5.2 高级重锻石（`reroll_stone_advanced`）

| 项 | 规则 |
|----|------|
| 消耗 | 1× 高级重锻石 |
| 重滚范围 | **基础词条 + 强化词条（强化加成 `bonus`）** |
| 强化层结构 | `enhance_level` 与 `spent_materials` **保留**（强化阶不因重锻清零）；仅各方向数值按规则重抽 |
| 数值分布 | **偏高**：相对标准区间，采样偏向高位（见下） |
| 可搭配锁定 | ✅ 可与锁定重锻石同用（可锁基础词条和/或强化方向） |

**偏高数值（策划意图，实现用 JSON 系数）：**

| 层 | 普通重锻 / 掉落 | 高级重锻建议 |
|----|-----------------|--------------|
| 基础词条 | 区间均匀或现有分布 | 在 `[min, max]` 内使用偏高采样（如 Beta/三角分布偏向 max，或有效区间改为 `[min+0.3×span, max]`） |
| 强化加成 | — | 按当前强化阶应有的每级区间重抽，同样偏高；总加成 ≈ 各方向重抽之和，**不超过**「该阶理论满值 × 上限系数」（防爆炸）；上限系数**占位待定**（V1.8，尚未定值） |

原则：高级石应让玩家明显感到「更容易出好数」，但不是保底满值。

### 5.2.1 品阶标准区间（V1.14 新增）

### 5.3 锁定重锻石（`reroll_stone_lock`）

| 项 | 规则 |
|----|------|
| 单独使用 | **禁止**；必须与普通石或高级石同一次提交 |
| 消耗 | 每锁定 **1 条**词条（或 1 个强化方向键）消耗 **1×** 锁定石 |
| 锁定上限 | **硬性：一次最多使用 2 个**锁定重锻石（最多锁 2 条）；超过则 UI 禁止确认 |
| 锁定对象 | UI 勾选：基础词条字段和/或强化 `bonus` 中的方向键 |
| 效果 | 被锁条目数值 **原样保留**；未锁条目按所用主石规则重滚 |

**组合示例：**

| 放入 | 行为 |
|------|------|
| 仅普通石 | 重滚全部基础词条，保留强化 |
| 仅高级石 | 重滚全部基础 + 全部强化加成（偏高） |
| 普通石 + 锁定石×1 | 锁 1 条基础词条，其余基础词条重滚；强化不动 |
| 高级石 + 锁定石×2 | 锁 2 条（可混基础/强化），其余按高级规则重滚 |
| 仅锁定石 | **非法**，UI 禁用确认 |

### 5.4 对照总表

| | 普通重锻石 | 高级重锻石 | 锁定重锻石 |
|--|------------|------------|------------|
| 基础词条 | 重滚（标准分布） | 重滚（偏高分布） | 不单独生效 |
| 强化加成 | 保留 | 重滚（偏高；阶数保留） | 不单独生效 |
| 须搭配 | — | — | 普通或高级 |

## 六、粉碎回收

| 项 | 规则 |
|----|------|
| 操作费用 | **免费**（V1.8 定稿）：粉碎不消耗任何材料/费用，仅按规则结算返还 |
| 可粉碎条件 | `enhance_level >= 1`（或 `spent_materials` 非空） |
| 品阶碎片 | **50%** 返还已使用量（见 §6.1） |
| 类型精华 | **25%** 返还；因每次强化只消耗 1 个，按「每份独立概率」结算（见 §6.2） |
| 重锻石 | **不参与**粉碎返还 |
| 装备本体 | 粉碎后 **销毁装备**（V1）；可选后续「粉碎只剥强化、保留白板装备」 |

### 6.1 品阶碎片返还（50%）

记 `spent` = 该装备累计消耗的某档品阶碎片数量，`rate = 0.5`。

| 情况 | 返还 |
|------|------|
| `spent = 0` | 0 |
| `spent = 1` | 无法返还 0.5 → **50% 概率返还 1 个** |
| `spent ≥ 2` | `floor(spent * 0.5)` 必返；若 `spent` 为奇数，另有 **50% 概率再返 1**（处理半个） |

等价写法：`必返 = floor(spent / 2)`，`再掷一次 50% 得 +1` 当且仅当 `spent % 2 == 1`。

### 6.2 类型精华返还（25%）

约定：**单次强化固定消耗 1 个**对应类型精华（不再按阶递增堆在一次提交里）。  
`spent_essence` = 历史上成功/失败强化累计吞掉的精华个数。

| 规则 | 说明 |
|------|------|
| 结算方式 | 对每一份已消耗精华，**独立以 25% 概率返还 1 个**（Binomial / 逐份掷骰） |
| 为何不用「总数 × 25% 再取整」 | 每次只用 1 个，小数无意义；概率返还更直观，也避免 `spent=1` 时 `floor(0.25)=0` 永远空手 |

示例：

| 累计消耗精华 | 期望返还 | 实际 |
|--------------|----------|------|
| 1 | 0.25 | 25% 得 1，否则 0 |
| 4 | 1.0 | 各掷 4 次 25%，约 0～4 个 |

### 6.3 经济意图

- 品阶碎片半额回流，鼓励「试错后粉碎重来」  
- 精华回流低（25% 概率/份）；因类型精华掉率充裕（§8.2 燃料论），精华不是主瓶颈，主瓶颈在品阶碎片  
- 重锻石不回流，避免无限洗词条套利

## 八、掉落与来源

### 8.1 双通道（必须分开）

| 通道 | 配置 | 掉什么 |
|------|------|--------|
| A. 饰品 GLM | `loot/drop_table.json` | 成品饰品（现有） |
| B. 实体战利品表 | `loot_tables/entities/{elite}.json` | **锻造材料**（新建） |

材料 **不要** 写入 `drop_table.json`，以免与饰品池、品阶权重耦合。

### 8.2 材料掉率（V1.16 定稿，独立体系）

**三档材料独立判定**，比例固定为 **类型精华 : 品阶碎片 : 属性精华 = 6 : 2 : 1**（即类型精华是碎片的 3 倍、属性精华是碎片的一半）。不再挂靠饰品 `drop_chance`（V1.16 定稿；旧「材料掉率 ≈ 饰品 ×1.25~1.5」作废）。

| 怪物档 | 类型精华掉率 | 品阶碎片掉率 | 属性精华掉率 |
|--------|:---:|:---:|:---:|
| 原版普通怪（19 只） | **20%** | **6.7%** | **3.3%** |
| 原版精英向（15 只） | **35%** | **11.7%** | **5.8%** |
| 自定义精英·普通档（7 只） | **60%** | **20%** | **10%** |
| 自定义精英·高档（5 只） | **80%** | **26.7%** | **13.3%** |
| 自定义精英·顶级（2 只） | **100%（保底 1～3）** | **50%** | **25%** |
| Boss | **100%（保底 1～3）** | **50%** | **25%** |
| 高难宝箱（高级/稀世） | **30%** | **10%** | **5%** |
| 低阶宝箱（地牢/村庄/废弃矿井） | ❌ | ❌ | ❌ |

> 顶级精英与 Boss 同档：类型精华**必掉**（保底 1～3），保证任何进度下锻造台不断料。

**数量规则：**

| 材料 | 数量 |
|------|------|
| 类型精华 | 普通怪/精英/宝箱每次 1～2 个；顶级精英与 Boss 1～3 个 |
| 品阶碎片 | 每次 1 个；顶级精英与 Boss 1～2 个 |
| 属性精华 | 每次 1 个 |

**子类分配：**

| 材料 | 子类规则 |
|------|----------|
| 类型精华 | **饰品 / 武器 / 护甲精华 = 1:1:1 均分**（V1 仅饰品精华可强化，武器/护甲精华先囤积，强化挂「未开放」提示；后续开放无需改掉率） |
| 品阶碎片 | 按品阶权重 **6 / 5 / 4 / 3 / 2 / 1**（残破→至臻）细分 |
| 属性精华 | 按 §4.3 方向权重细分（可后调） |

**设计意图：**

- **类型精华是「燃料」，管够**——每次强化消耗 1 个（无论成败），高频耗材必须高频产出；溢出无副作用（囤积用于以后武器/护甲）。
- **品阶碎片是「节奏卡点」**——决定强化成功率（每片 +25%），掉率仅精华的 1/3，玩家按碎片进度推进强化。
- **属性精华是「战略资源」**——仅碎片的 1/2，决定跨属性维度，稀缺性天然成立。
- **玩家永远不会因缺类型精华而停滞**：顶级精英/Boss 保底，普通精英档 60% 已接近「基本不断」。

重锻石掉率定稿见 §8.2.1（V1.6）。与 §8.2 主体约束的关系：重锻石与饰品/精华用途不同（重锻仅滚基础词条、消耗量大），**不**按「少于精华」的稀缺标尺约束；仅保留「高级稀于普通」「锁定≈高级」两条相对关系。


- **无共享精英基类**：各怪继承不同原版 Mob，合理，不必强造 `EliteMob`  
- **痛点是 N 处同步**：注册 / 事件 / biome / loot / drop_table / lang / renderer  
- **`life_leecher`**：仅 drop_table 死配置，无实体  

### 10.2 为锻造材料：是否必须大改？

| 结论 | 说明 |
|------|------|
| **材料掉落：不必大改架构** | 填 `loot_tables/entities/*.json` 即可与 GLM 并行 |
| **扩展便利：建议小改** | 降低「每加一种怪 / 一种材料」的同步成本 |

### 10.3 建议改动（按优先级）

| 优先级 | 改动 | 目的 |
|--------|------|------|
| P0 | 清空或实装 `life_leecher` 掉落条目 | 避免校验噪音与假配置 |
| P0 | 为已注册精英补材料 loot pool | 锻造经济运转 |
| P1 | 补齐后波 `biome_modifier`（或显式标记「仅召唤」） | 材料有稳定来源 |
| P1 | 抽取 `EliteSpawnRules.night()` / `lowLight()` | 减少 `EliteEntityEvents` 复制 |
| P2 | 可选 `EliteCatalog`（id → 属性、spawn、loot 标签、材料主题） | 新怪只改一处登记 + JSON |
| P2 | 生成蛋 / 调试指令 | 测材料掉落 |
| 不做 | 强行统一继承树 | 父类异构，收益低、风险高 |

### 10.4 推荐目标结构（不强制一次做完）

```text
entity/
  ModEntities.java              # 注册
  EliteCatalog.java             # 可选：元数据登记
  EliteEntityEvents.java        # 读 Catalog 或共用 SpawnRules
  EliteSpawnRules.java          # night / lowLight 共用
  monster/*Entity.java          # 仅行为差异
data/
  neoforge/biome_modifier/      # 一怪一文件或按组
  evolutionary_mod/loot_modifiers/    # 重锻石掉落（原版普通怪/精英向/宝箱），不污染原版战利品表
  evolutionary_mod/loot_tables/entities/  # 精英/Boss 材料池
  evolutionary_mod/loot/drop_table.json   # 仅饰品
```

**一句话：** 锻造材料适配 **以填 loot 表为主**；精英侧做 **P0/P1 清理与去重** 即可明显利于后续扩展，无需推倒重来。

## 十一、life_leecher 处理决议

### 11.1 它是什么

`life_leecher`（命名语义：生命吸取者 / 吸血精英）**仅存在于**：

- `data/evolutionary_mod/loot/drop_table.json`
- `AccessoryDropTable` Java 回退表  

**不存在：** `ModEntities` 注册、实体类、loot_table 文件、biome_modifier、lang。

结论：**未实装的预留掉落键 / 死配置**，当前不会在游戏中触发（没有该 loot_table_id 的查询来源）。

### 11.2 决议（策划默认）

| 选项 | 说明 | 推荐 |
|------|------|------|
| A. 删除两端配置 | 保持表与实体一致 | ✅ V1 前执行 |
| B. 完整实装该精英 | 需实体+生成+loot+材料主题（吸血/生命） | 可列为后续精英 |

在实装吸血主题精英前，**不要**只留 drop_table 空键。

## 搁置说明与实装注意事项

当前状态为 **待实装策划**。实装前确认：

1. 强化层用独立 DataComponent；普通重锻只动 `AccessoryAttributes`，高级重锻才动强化 `bonus`  
2. 锁定石不可单独提交；须与普通/高级石同次消耗；**一次最多 2 个**  
3. 材料走 entity loot，饰品走 GLM，两套配置勿合并  
4. 通用强化禁止产出下一掉落品阶同款物品；升阶仅白名单  
5. 同步更新：`docs/dev/开发者指南-精简版.md`、双语 lang、Patchouli 引导书  
6. 验证：三种重锻；成功率跨两档 10 份仍 &lt;50%；粉碎概率边界  
7. **实装重锻石掉落时，同步修复饰品 GLM 击杀场景幸运不生效**：击杀时 `THIS_ENTITY` 为被击杀怪物而非玩家，现有代码 `instanceof Player` 判定拿不到幸运值，需补 `KILLER_ENTITY` 分支（见 §8.2.1 规则 2）
8. **强化范围 = 物品已有属性**（V1.14）：强化方向池受物品基础词条约束，跨属性只能走属性精华（§3.5/§4.5）；属性精华添加的属性需能正确进入强化方向池与重锻维度保留逻辑
9. **属性精华添加占用强化次数**：与强化共用 +10 上限（§4.5），实现时需在 `FORGE_ENHANCEMENT` 中区分「强化操作」与「精华添加」两种计数来源（如 `enhance_level` 统一 +1，另记 `essence_added` 用于 UI 展示/重锻判断）

## 策划案总结

| 模块 | 一句话 |
|------|--------|
| 强化 | 同物品叠层，上限 +10；成功率由饰品品阶×同名品阶碎片×数量决定 |
| 材料 | 3 类精华 + **6 种品阶碎片（残破～至臻）** + 三种重锻石；重锻石掉率见 §8.2.1 |
| 普通重锻 | 只重滚基础词条，保留强化 |
| 高级重锻 | 重滚基础 + 强化加成，数值偏高；强化阶保留 |
| 锁定重锻 | 搭配普通/高级；一次最多用 2 个锁定石 |
| 粉碎 | 销毁装备；品阶碎片 50% 回流；类型精华每份 25% 概率回流；重锻石不返 |
| 升阶 | 白名单特例，与强化分流 |
| 精英 | 填空 loot + 清 life_leecher + 小幅去重即可适配 |

# Blockbench 建模与提示词规范

> 适用范围：凡是涉及 **3D 建模、Blockbench 使用、贴图建模、动画、PBR 材质、Hytale/Blockbench 相关导出** 的需求，在生成提示词、执行 MCP 操作、设计模型方案前，必须先阅读本规范。
>
> 目的：让后续生成的提示词更适合 Blockbench 真实建模流程，减少“概念图好看但无法落地”的情况。

---

## 1. 总原则

1. **先看规范，再写提示词。**
   - 任何与 Blockbench 相关的提示词，都应先按本规范理解目标，再输出。
2. **提示词必须面向可建模性，而不是只追求画面好看。**
   - 优先考虑：轮廓清晰、结构可拆分、骨骼可动、材质可分区、导出可用。
3. **Blockbench 优先级高于“艺术感”。**
   - 过多碎细节、连续曲面、不可拆分的大面积装饰、真实毛发/布料褶皱都要避免。
4. **提示词要服务于实际资源落地。**
   - 最终目标通常是：`Minecraft` 风格模型、资源包贴图、实体模型、可动画模型、可导出模型。

---

## 2. 何时必须读取本规范

以下任一情况出现时，先读本规范再继续：

- 要生成或改写 **Blockbench 建模提示词**
- 要为 **Minecraft 3D 物品 / 生物 / Boss / 装饰物** 写提示词
- 要设计 **适合 MCP 驱动 Blockbench** 的建模方案
- 要对模型做 **分组、骨骼、动画、UV、贴图、PBR** 相关说明
- 要把一个美术概念转成 **可执行的 Blockbench 步骤**

---

## 3. 相关 Skill 的读取顺序

涉及 Blockbench 时，按下面顺序选用 Skill：

### 3.1 必读

1. `blockbench-use`
   - 只要会调用 `mcp__blockbench__*` 工具，就必须先加载。
   - 负责前置检查、技能路由、checkpoint、导出闭环。

2. `blockbench-mcp-overview`
   - 当你需要了解 Blockbench MCP 有哪些能力、工具、资源时读取。
   - 适合做方案总览和起步判断。

### 3.2 按需求加载

- `blockbench-modeling`
  - 建模、几何、分组、骨骼结构、cube/mesh/sphere/cylinder、细节结构。
- `blockbench-texturing`
  - 贴图、UV、颜色绘制、渐变、图案、纹理层。
- `blockbench-animation`
  - 动画、关键帧、骨骼运动、待机/攻击/死亡。
- `blockbench-pbr-materials`
  - PBR 材质、normal/height/MER、texture_set.json。
- `blockbench-hytale`
  - Hytale 格式、附件、quads、特殊格式导出。
- `blockbench-development`
  - 仅用于写 Blockbench 插件，不用于普通 MCP 建模。

### 3.3 选择规则

如果一个任务同时涉及多个域，必须同时加载多个 Skill。

例：

- “做一个会挥刀的 Boss” → `blockbench-use` + `blockbench-mcp-overview` + `blockbench-modeling` + `blockbench-animation`
- “做一个发光的矿石方块” → `blockbench-use` + `blockbench-mcp-overview` + `blockbench-modeling` + `blockbench-texturing`
- “做 Bedrock RTX 材质” → `blockbench-use` + `blockbench-mcp-overview` + `blockbench-texturing` + `blockbench-pbr-materials`

## 4. Blockbench 友好型提示词原则

### 4.1 必须写清楚的内容

生成提示词时，至少要明确：

- 物品/生物/建筑的 **类型**
- 目标风格：`Minecraft / Blockbench / voxel / low-poly`
- **用途**：物品、实体、Boss、饰品、武器、方块、装饰物、附件等
- **尺寸或比例感**：小物件 / 人形 / 巨型 / 便携型 / 悬浮型
- **是否需要动画**：待机、攻击、漂浮、摆动、死亡、开合等
- **结构拆分**：头、躯干、四肢、武器、背饰、核心、光效等
- **材质分区**：金属、石头、晶体、皮革、骨质、能量核心、布料等
- **色彩主轴**：主色、辅色、高光色、发光色
- **轮廓要求**：尖锐 / 圆润 / 厚重 / 轻盈 / 对称 / 非对称
- **可读性要求**：远看也能识别，不能糊成一团

### 4.2 要避免的描述

尽量不要写这些会让 Blockbench 难以落地的内容：

- 太多微小鳞片、碎片、铆钉、纹理坑点
- 大面积不可分割的连续曲面
- 写实毛发、写实布料褶皱、真实皮肤细节
- 复杂到无法拆组的装饰边框
- 纯视觉效果词太多，但结构信息很少
- “像某某电影里的怪物”这类只能看感觉、不能建模落地的描述

### 4.3 推荐的结构表达方式

建议按下面顺序描述：

1. **整体轮廓**
2. **主体结构**
3. **关键部件**
4. **材质与颜色**
5. **发光/能量/特效部分**
6. **动画友好点**
7. **禁止项**

例如：

- “整体是四足重甲兽，背部有发光脊骨，头部左右对称角，胸口核心独立发光，四肢分组清楚，适合做怒吼和冲撞动画。”
- “整体是悬浮核心型 Boss，冠冕、披风碎片、能量环必须分组，不能做传统双腿。”

## 5. 面向不同目标的提示词标准

### 5.1 3D 物品 / 材料

适用于：精华、碎片、徽章、铸币、宝石、袋子、匣子等。

要求：

- 剪影必须独特
- 小尺寸可识别
- 颜色区分明显
- 表面细节不要过碎
- 适合做 16x16 或 32x32 的资源贴图模型

提示词重点：

- 大块面
- 强轮廓
- 简洁装饰
- 明确材质
- 透明背景 / 单体居中

### 5.2 生物 / Boss

要求：

- 头、躯干、四肢、背饰分组清晰
- 结构适合骨骼动画
- 动作关键部位可单独驱动
- 先有强剪影，再有局部造型
- 不要把所有细节堆在同一个部位

提示词重点：

- Boss 的压迫感
- 可动部件
- 动画表现点
- 攻击姿态
- 待机姿态

### 5.3 建筑 / 装置 / 机关

要求：

- 模块化
- 分层结构清晰
- 便于复制、旋转、镜像
- 机关部件要能单独命名与运动

提示词重点：

- 主体、支架、装饰、动力核心、开关件
- 对称结构
- 可扩展结构

### 5.4 PBR / 发光材料

要求：

- 明确区分 color / normal / height / mer
- 金属、玻璃、晶体、石头材质要分开描述
- 发光区域必须标清楚
- 粗糙度和金属感要可控

提示词重点：

- 哪些区域发光
- 哪些区域高反光
- 哪些区域粗糙
- 哪些区域是透明/半透明

## 6. Blockbench 建模提示词模板

> 这是推荐格式。以后凡是要给 AI 生成 Blockbench 方案，可以优先按这个模板写。

### 6.1 物品模型模板

**模板：**

- 这是一个 Minecraft / Blockbench 风格的物品模型。
- 说明它是什么物品。
- 说明整体轮廓。
- 说明主要材质和颜色。
- 说明关键装饰和核心发光点。
- 说明需要哪些部件分组。
- 说明是否需要动画。
- 说明哪些细节不要做。
- 说明最终用途是图标、掉落物、手持物还是展示模型。

**例子：**

一个 Minecraft 风格的物品模型，主体是一枚圆形刻面宝石，透明晶体外壳，内部有发光核心，中心悬浮一个小型徽记。模型必须保持圆润清晰的剪影，表面只有少量大面切割，不要做成瓶子或布袋。请把外壳、内核、徽记分成独立部件，适合后续做轻微旋转或呼吸发光动画。整体用于游戏内物品图标展示。

### 6.2 Boss 模型模板

**模板：**

- 这是一个 Minecraft Boss 模型。
- 先写清楚体型和姿态。
- 再写头部、躯干、四肢、背部、武器、冠冕、核心等部件。
- 明确分组，方便骨骼动画。
- 说明发光点和材质区分。
- 明确不要碎得太细。

**例子：**

一个 Minecraft Boss 模型，体型巨大，整体是漂浮的黑暗君王形态。头部是断裂冠冕，胸口是发光核心，左右手臂是能量化的长臂，背后漂浮破碎披风和冠冕碎片。请将冠冕、核心、披风碎片、双臂、下半身雾状结构分成多个清晰部件，便于后续添加漂浮、展开、爆发攻击动画。不要写实，不要复杂毛发，不要过碎的装甲纹样。

### 6.3 机关 / 装置模板

**模板：**

- 这是一个 Minecraft 风格机关模型。
- 强调模块化、左右对称、可拆解。
- 说明核心动力部件。
- 说明可运动部件。

## 7. 提示词生成时的硬性检查清单

每次生成 Blockbench 相关提示词前，先检查这些问题：

- [ ] 这是物品、实体、Boss、装置还是 PBR 材质？
- [ ] 是否必须拆分成多个部件？
- [ ] 是否需要骨骼动画？
- [ ] 轮廓是否足够清晰？
- [ ] 是否存在“画面好看但无法建模”的细节？
- [ ] 颜色是否与同系列其它物品明显区分？
- [ ] 材质是否写明（金属/晶体/石头/布料/能量）？
- [ ] 是否写明尺寸、比例和用途？
- [ ] 是否说明了禁止项？
- [ ] 是否适合 Minecraft 的方块/体素表达？

如果有任意一项不明确，先补齐，再输出提示词。

## 8. 针对本项目的额外约定

### 8.1 Minecraft 物品类

本项目的材料、货币、徽章、碎片、匣子、袋子、刷怪蛋等，生成提示词时应优先考虑：

- **16x16 可读性**
- **透明背景**
- **单体居中**
- **系列内统一，但彼此有差异**
- **不要过度细腻**

### 8.2 Boss / 生物类

Boss 设计提示词必须明确：

- 轮廓
- 分组
- 可动画部件
- 材质分区
- 发光核心
- 禁止过碎细节

### 8.3 给 Blockbench MCP 的提示词建议

如果目标是让 MCP 直接帮你建模，提示词最好包含：

- 模型类型（物品 / 实体 / Boss）
- 格式方向（cube / mesh / Hytale / PBR）
- 是否需要动画
- 是否需要纹理
- 预期导出格式
- 结构分组要求
- 需要保存 checkpoint 的复杂程度

---

## 9. 推荐的 Prompt 输出格式

以后凡是和 Blockbench 相关，建议提示词按下面结构输出：

1. **目标**：这是做什么的
2. **风格**：Minecraft / voxel / Blockbench
3. **结构**：主体、部件、分组
4. **材质**：金属、晶体、石头、布料、发光核心
5. **颜色**：主色、辅色、高光色
6. **动画**：需要什么动作
7. **禁止项**：不要什么
8. **用途**：图标、手持、掉落、Boss、展示

---

## 10. 最后提醒

- 这个规范是给 **Blockbench / MCP 建模类提示词** 用的，不是给纯 2D 插画用的。
- 如果是纯贴图、纯 icon、纯平面 AI 图，就不要强行套用本规范的 3D 结构规则。
- 如果任务跨越建模 + 贴图 + 动画，要把相关 Skill 都纳入考虑，而不是只写一个模糊提示词。

---

## 11. 维护说明

当 Blockbench 技能库发生变化、项目新增新的模型类型、或需要新的导出格式时，应同步更新本规范中的：

- Skill 读取顺序
- 提示词模板
- 检查清单
- 项目约定
- 禁止项

这样后续生成的提示词会一直稳定、可执行、适合真实建模。
